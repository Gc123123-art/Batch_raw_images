# 合并 task_results 到 tasks（image_url 存 JSON）

## 目标结构

tasks 表（去掉 user_id，加 account；图片链接集中到 image_url 一列，JSON 对象按序号存）：

```sql
tasks (
  id              SERIAL PRIMARY KEY,      -- 保留自增 id 作为技术主键
  account         TEXT NOT NULL,           -- 替代 user_id，关联 users.account
  prompt TEXT, reference_image TEXT, shared_reference_image TEXT,
  size TEXT, n INT, total_count INT, completed_count INT,
  status TEXT, amount INT, remark TEXT, batch INT,
  image_url       TEXT DEFAULT '{}',       -- JSON: {"1":"https://...","2":"https://..."}
  error           TEXT DEFAULT '',         -- 任务级错误（原首条失败错误）
  updated_at TEXT, created_at TEXT
)
```

> 说明：**保留 id 列**。一个账号有多条任务（任务列表分页、任务详情页 `?id=`、图片接口 `/api/files/{id}/{seq}` 都靠它定位），如果连 id 也删掉，同一账号的多条任务无法区分，前端所有链接和缓存逻辑都要推翻重做。删掉的语义上的"任务归属外键 user_id"改用 account 表达。如果你坚持要物理删除 id 列，我可以在实施时改成 (account, created_at) 复合定位，但改动面和风险都大很多。

`task_results` 表整体删除（先迁移后 DROP）。

## 改动清单

### 1. backend/app/db/database.py
- 两套 DDL（Postgres/MySQL）：tasks 加 `account`、`image_url`（默认 `'{}'`）、`error`，删 `user_id`；删除 task_results 建表语句。
- 删函数：`get_task_results`、`get_task_result_by_seq`、`update_task_result`、`create_task` 里预插 total_count 行的循环。
- 改函数（全部 user_id → account）：
  - `create_task(account, ...)`：不再预插子行。
  - `update_task_result(task_id, seq, image_url)` → `set_task_image_url`：读 tasks.image_url JSON，`json[str(seq)] = url` 写回。
  - `get_task_results` 改为从 tasks 行派生：解析 image_url JSON，生成 `[{seq, image_url, status: 'success'}]`，未完成且 seq>已生成数的算 pending，结束后缺失的算 failed —— 保持 API 返回结构不变，前端几乎不用动。
  - `get_user_tasks`、`delete_user`、`record_deduction`、`get_user_deductions`（task 关联字段改 account）、`list_incomplete_tasks` 等全部换列名。

### 2. backend/app/api/routes/tasks.py
- `_run_task_background`：成功时调 `set_task_image_url`；失败时把首条 error 写 tasks.error；resume 的 skip-set 从 image_url JSON 的 key 集合取。
- 各路由 ownership 检查 `task["user_id"] != user["id"]` → `task["account"] != user["account"]`。
- 失败任务详情的 error 直接读 tasks.error。

### 3. backend/app/api/routes/upload.py
- `/api/files/{task_id}/{seq}`：从 tasks.image_url JSON 取第 seq 个 URL（原有的 image_path 文件分支是遗留死代码，一并删除）。

### 4. 前端（frontend/）
- 后端保持 `/api/tasks/{id}/results` 返回 `{task, results:[{seq,image_url,status}]}`，dashboard.html / task-detail.html 基本不动；只把失败的 per-image error 展示改为任务级 error 文案。

### 5. 数据迁移脚本（backend/scripts/migrate_merge.py，跑一次）
对远程库（8.137.70.163:5433）执行：
1. `ALTER TABLE tasks ADD COLUMN account / image_url / error`；
2. 回填 `account` ← users 表按 user_id 关联；`image_url` ← 聚合 task_results 中 status='success' 的行成 JSON；
3. 回填 `error` ← 首条失败错误；
4. 校验行数/JSON 完整性后 `DROP TABLE task_results`；
5. 删除 tasks.user_id 列。

### 6. 收尾
- 删除 database.py 中所有 task_results 相关代码与注释，启动时迁移列表同步更新。

## 风险与验证
- 迁移脚本先 dry-run 打印将写入的 account/image_url 样例，确认无误再执行 DROP。
- 验证：新建单张任务、批量任务各一个，确认 image_url JSON 写入、详情页/图片下载/ZIP 打包正常，历史任务（迁移数据）详情页可打开。
