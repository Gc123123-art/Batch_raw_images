# BOLI AI 批量生图平台 — 安全加固说明

> 本文档记录 2026-08-07 对本项目（`batch_generator`）进行的安全加固改动，
> 以及部署到云服务器前必须完成的配置项。
> 适用版本：api_server.py v1.1.0（本次加固后）

---

## 一、为什么需要加固

代码原本具备基本安全设计（bcrypt 密码加密、JWT 登录、接口权限校验），
但存在 2 个高危默认密钥和若干宽松配置，**直接暴露到公网云服务器存在被攻击风险**：

| 等级 | 问题 | 风险 |
|------|------|------|
| 🔴 致命 | 管理员密钥是公开默认值 `admin-secret-key-2026` | 任何人可调用充值/改余额/删用户接口 |
| 🔴 致命 | JWT 签名密钥是公开默认值 | 可伪造任意用户 token，直接登录任意账号 |
| 🟠 高 | CORS 允许所有来源 | 任意网站可跨域调用 API |
| 🟠 高 | 无 HTTPS | token 明文传输，易被中间人窃取 |
| 🟠 中 | 上传接口无登录校验 | 任何人可上传文件占用服务器磁盘 |
| 🟡 中 | 无登录频率限制 | 账号可能被暴力破解 |
| 🟡 低 | ZIP 解压无大小限制 | zip 炸弹可占满磁盘 |

## 二、本次代码改动清单

### 1. 新增 `app/secrets.py` — 密钥自动管理模块

- **问题**：JWT_SECRET / ADMIN_KEY 默认值写死在代码里，公开可见。
- **改法**：新增密钥管理模块，读取优先级：
  1. 环境变量（生产推荐）
  2. `.secrets/` 目录下已持久化的密钥文件
  3. 自动生成 64 位随机密钥并写入 `.secrets/` 文件（首次启动自动完成）
- **效果**：密钥不再有默认值；重启不丢失；部署无需手工生成。

### 2. `app/auth.py` — JWT 签名密钥安全化

- 删除默认密钥 `dongli-ai-batch-generator-secret-key-change-me`
- 改为 `get_or_create_secret("JWT_SECRET", "jwt_secret")`
- 生产可通过环境变量 `JWT_SECRET` 覆盖

### 3. `api_server.py` — 管理密钥安全化

- 删除默认管理密钥 `admin-secret-key-2026`
- 改为 `get_or_create_secret("ADMIN_KEY", "admin_key")`
- 生产可通过环境变量 `ADMIN_KEY` 覆盖

### 4. `api_server.py` — CORS 白名单可配置

- 由 `allow_origins=["*"]` 改为 `CORS_ORIGINS` 环境变量（逗号分隔）
- 默认仅允许本地开发域名：`http://localhost:8001, http://127.0.0.1:8001`
- 生产设置为前端实际域名，例如：`https://img.example.com`

### 5. `api_server.py` — 上传接口增加登录鉴权

- `/api/upload`、`/api/upload/zip` 增加 `Depends(get_current_user)`
- 未登录调用返回 401（已验证）

### 6. `api_server.py` — 登录/注册限流（防暴力破解）

- 同一 IP 连续失败 `LOGIN_MAX_ATTEMPTS`（默认 5）次，锁定 `LOGIN_LOCK_MINUTES`（默认 5）分钟
- 登录成功后自动清除失败记录；内存记录自动清理过期项
- 兼容 Nginx 反代的 `X-Forwarded-For` 真实 IP 获取

### 7. `api_server.py` — 上传大小与 ZIP 解压限制

- 单文件上传：改为 `read(10MB+1)` 限量读取，超大文件不会打爆内存
- ZIP 上传：压缩包原始大小 ≤ 50MB；解压后总大小 ≤ 200MB；文件数 ≤ 300（防 zip 炸弹）

### 8. `api_server.py` — 启动安全信息提示

- 启动日志打印密钥来源（环境变量或 .secrets 文件，不打印密钥本身）、CORS 白名单、限流参数

## 三、部署云服务器配置清单（必读）

### 1. 设置环境变量（推荐，也可省略，密钥会自动生成到 .secrets/）

```bash
# 在 systemd 服务 / docker / shell 中设置
export JWT_SECRET="$(openssl rand -base64 48)"
export ADMIN_KEY="$(openssl rand -base64 48)"
# CORS 设为前端实际域名
export CORS_ORIGINS="https://img.example.com"
```

### 2. HTTPS（必须）

用 Nginx 反向代理 + Let's Encrypt 免费证书：

```nginx
# /etc/nginx/sites-available/dongli.conf
server {
    listen 80;
    server_name img.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name img.example.com;

    ssl_certificate     /etc/letsencrypt/live/img.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/img.example.com/privkey.pem;

    # 后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 1200s;   # 生图耗时长，需调大
    }

    # 前端静态页面
    location / {
        proxy_pass http://127.0.0.1:8001;
    }
}
```

证书申请：`sudo apt install certbot python3-certbot-nginx && sudo certbot --nginx -d img.example.com`

### 3. 防火墙（重要）

- **关闭公网对 8000 / 8001 端口的访问**（仅本机 Nginx 回环访问）
- 只开放 80 / 443：

```bash
# 云厂商安全组：只放行 80、443
# 服务器本地：
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw deny 8000/tcp
sudo ufw deny 8001/tcp
```

### 4. 前端地址配置

前端 [web_frontend/js/config.js](web_frontend/js/config.js) 的 `API_BASE` 默认是 `http://localhost:8000`，
**生产部署必须改为线上 API 域名**，例如：

```js
const API_BASE = window.API_BASE || 'https://api.example.com';
```

推荐在页面加载 `config.js` 之前注入 `window.API_BASE`（index.html 内联脚本），便于按环境切换。

### 5. 其他注意事项

- `.secrets/` 目录权限：`chmod 700 .secrets`（Linux），确保 web 用户可读
- 供应商 API KEY 已入库（`api_providers` 表），不要把数据库 `data.db`、`.secrets/` 提交到 Git
- 生产环境管理员密钥（`ADMIN_KEY`）和 `JWT_SECRET` 通过 systemd `EnvironmentFile` 注入，不写入项目代码
- 建议在服务器上补充 .gitignore：
  ```
  data/
  .secrets/
  backend/.secrets/
  ```
- 数据库 `data.db` 定期备份（可用 SQLite 的 `.backup` 命令或复制文件）

## 五、遗留说明

- 登录限流为**进程内内存版**（单实例有效）；若未来多实例部署，可改为 Redis 存储
- 上传文件无病毒扫描；若面向公网开放注册，建议后续增加内容审核或人工审核
- 注册接口目前开放（业务需要）；若仅内部使用，可通过注册开关环境变量关闭
