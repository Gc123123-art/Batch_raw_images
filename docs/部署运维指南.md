# BOLI AI 部署运维指南

> 记录当前生产环境的整体架构、常驻进程、以及「改代码后如何覆盖上传」的完整流程。
> 更新日期：2026-08-15

---

## 1. 背景：为什么要搞 frp 代理

**问题**：云服务器（阿里云 8.137.70.163）上生成图片报网络错误，本地却正常。

**根因**：小扳手中转站 `xibapi.com` 对**阿里云机房 IP** 的图片生成接口
（`/v1/images/generations`、`/v1/images/edits`）实施风控，直接 `ConnectionResetError(10054)` 断开；
而**家庭宽带 IP 不受限制**，所以本地一切正常。

**解法**：让云服务器通过 frp 隧道，把请求转发到本地家庭电脑的 HTTP 代理再访问小扳手，
从而"借用"家庭宽带 IP 绕过风控。

---

## 2. 整体架构

```
用户浏览器
    │  http://ai.legouhou.cn
    ▼
┌─────────────────────────────────────────────┐
│ 云服务器 8.137.70.163（阿里云）                 │
│                                             │
│  Nginx（宝塔）                                 │
│   ├─ 前端静态文件  C:\wwwroot\BoliAi\frontend │
│   └─ /api/ 反向代理 → 127.0.0.1:8000          │
│                                             │
│  FastAPI 后端（uvicorn 8000 端口）             │
│    C:\wwwroot\BoliAi\backend                 │
│    config.env 含 HTTPS_PROXY=127.0.0.1:8899  │
│         │                                    │
│         │ 走代理（HTTPS_PROXY）                │
│         ▼                                    │
│  frps（frp 服务端，C:\frp\，端口 7000）         │
└──────────────┬──────────────────────────────┘
               │ frp 隧道（服务器 7000 ⇄ 本地 7000）
               ▼
┌─────────────────────────────────────────────┐
│ 本地家庭电脑 192.168.1.38（24 小时开机）        │
│                                             │
│  frpc（frp 客户端，C:\frp\frpc.exe）           │
│   └─ 把本地 8899 映射到云服务器 8899            │
│                                             │
│  proxy.py（HTTP 代理，监听 127.0.0.1:8899）    │
│         │                                    │
│         ▼                                    │
│  小扳手 xibapi.com（家庭宽带 IP，不受风控）      │
└─────────────────────────────────────────────┘
```

请求链路：`前端 → 后端 → 127.0.0.1:8899 代理 → frp 隧道 → 本地 proxy.py → 小扳手`

> 向量中转站（api.vectorengine.cn）不受 IP 风控，走不走代理都行；代理对它是无感的（正常转发）。

## 3. 常驻进程清单（重启电脑后自动恢复）

| 位置 | 进程 | 用途 | 自启任务 | 守护任务 |
|------|------|------|---------|---------|
| 云服务器 | `frps.exe` | frp 服务端（隧道入口，端口 7000） | `BOLI_Frps` | `BOLI_Watch` |
| 云服务器 | `watch_backend.py` | 后端守护（自动重启/自恢复） | `BOLI_Backend_Watch` | `BOLI_Watch` |
| 云服务器 | FastAPI 后端 | 业务 API（端口 8000，由 watch_backend 拉起） | 随 watch 自启 | 由 watch 守护 |
| 本地电脑 | `frpc.exe` | frp 客户端（连服务器 7000，映射 8899） | `BOLI_Frpc` | `BOLI_Watch` |
| 本地电脑 | `proxy.py` | HTTP 代理（监听 8899） | `BOLI_Proxy` | `BOLI_Watch` |

### 3.1 frp 配置文件（要改必须两边一致）

**云服务器 `C:\frp\frps.toml`**（服务端）：

```toml
# frp 服务端配置（云服务器 8.137.70.163 用）
bindPort = 7000

# 认证 token（客户端必须一致）
auth.method = "token"
auth.token = "boli2026frp"
```

**本地电脑 `C:\frp\frpc.toml`**（客户端）：

```toml
# frp 客户端配置（本地电脑 192.168.1.38 用）
serverAddr = "8.137.70.163"
serverPort = 7000

# 认证 token（与服务端一致）
auth.method = "token"
auth.token = "boli2026frp"

# 把本地 8899 代理端口映射到云服务器的 8899
[[proxies]]
name = "proxy8899"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8899
remotePort = 8899
```

### 3.2 proxy.py（本地电脑）

```bat
:: 全局安装（已装好，重装才需要执行）
pip install --no-user --force-reinstall proxy.py

:: 启动命令（BOLI_Proxy 任务里就是这条）
:: --timeout 900 = 连接 15 分钟内无数据收发也不断开（必须加！防止生成耗时被 proxy 掐断）
"C:\Program Files\python\python.exe" -m proxy --hostname 0.0.0.0 --port 8899 --timeout 900
```

> proxy.py 必须装到**全局 site-packages**（不能用 `--user`），因为任务计划以 SYSTEM 身份运行，
> 读不到用户目录下的包。
>
> ⚠️ **`--timeout 900` 不能省**：proxy.py 默认空闲超时约 60 秒，而小扳手生成图片需要排队
> 1-2 分钟（请求发出后等响应期间连接无数据流动），会被 proxy 当成空闲连接直接掐断，
> 导致云端报"代理连接异常"。这是 2026-08-15 排障加上的。

### 3.3 云服务器后端 config.env

位置：`C:\wwwroot\BoliAi\backend\config.env`（**服务器专属文件，上传代码时绝不覆盖**）

```
CORS_ORIGINS=http://ai.legouhou.cn,http://8.137.70.163,http://localhost:8001,http://127.0.0.1:8001
DATABASE_URL=postgresql+psycopg2://postgres:boli123@8.137.70.163:5433/bunana_db?options=-csearch_path%3D%22AI%22
HTTPS_PROXY=http://127.0.0.1:8899
HTTP_PROXY=http://127.0.0.1:8899
```

> 后两行是代理配置，`requests` 库会自动读取，后端代码无需任何修改。
> 本地开发用的 `backend\config.env` 只有前两行，**不要**把代理行提交到本地（本地不需要）。

### 3.4 守护脚本（watch.bat，每分钟检查一次，挂了自动拉起）

**本地电脑 `C:\frp\watch.bat`**（守护 frpc + proxy）：

```bat
@echo off
:: frpc 进程不存在 -> 拉起
tasklist /FI "IMAGENAME eq frpc.exe" | findstr /i frpc.exe >nul
if errorlevel 1 schtasks /Run /TN "BOLI_Frpc"
:: frpc 进程在但到云服务器 7000 的隧道连接已断（进程在、连接断）-> 重启任务
:: （2026-08-15 增强：光查进程查不出"僵尸连接"，必须查 ESTABLISHED）
netstat -ano | findstr "8.137.70.163:7000" | findstr ESTABLISHED >nul
if errorlevel 1 schtasks /Run /TN "BOLI_Frpc"
:: proxy 8899 未监听 -> 拉起
netstat -ano | findstr ":8899" | findstr LISTENING >nul
if errorlevel 1 schtasks /Run /TN "BOLI_Proxy"
```

> ⚠️ **此增强版 watch.bat 需同步覆盖到代理机 `C:\frp\watch.bat`**（改完等下一分钟自动生效，
> 无需重启 BOLI_Watch 任务）。2026-08-15 事故就是 frpc 进程活着但隧道断开，旧 watch.bat
> 只查进程检测不出来，导致链路断了没自动恢复。

**云服务器 `C:\frp\watch.bat`**（守护 frps + 后端兜底）：

```bat
@echo off
tasklist /FI "IMAGENAME eq frps.exe" | findstr /i frps.exe >nul
if errorlevel 1 schtasks /Run /TN "BOLI_Frps"
netstat -ano | findstr ":8000" | findstr LISTENING >nul
if errorlevel 1 schtasks /Run /TN "BOLI_Backend_Watch"
```

两台机器各有一个 `BOLI_Watch` 任务计划，每分钟执行对应 watch.bat。

### 3.5 后端守护（watch_backend.py，秒级自动重启）

**云服务器 `C:\frp\watch_backend.py`**（源码在本地 `frp_setup\watch_backend.py`，改动后重新上传）：
由任务计划 `BOLI_Backend_Watch` 以 SYSTEM 身份后台常驻，每 2 秒检测一次：

- `backend\app\` 下任何 `.py` 变化 → 自动重启后端（代码改动立即生效）
- `config.env` / `.secrets\*` 变化 → 自动重启后端（配置/密钥改动立即生效）
- `requirements.txt` 变化 → 先 `pip install -r` 再重启（依赖更新也自动）
- 后端崩溃/被杀 → 自动拉起
- 后端运行日志写入 `C:\frp\backend.log`（排查问题看这个文件）

> 创建命令（已执行过，重装才需要）：
> ```
> schtasks /Create /TN "BOLI_Backend_Watch" /TR "\"C:\Program Files\python\python.exe\" C:\frp\watch_backend.py" /SC ONSTART /RU SYSTEM /RL HIGHEST /F
> ```

## 4. 日常状态检查

### 4.1 本地电脑（192.168.1.38）

```bat
:: proxy 是否在监听 8899
netstat -ano | findstr ":8899" | findstr LISTENING

:: frpc 是否在跑
tasklist | findstr frpc

:: frpc 到云服务器 7000 的隧道是否建立（进程在也可能连接断）
netstat -ano | findstr "8.137.70.163:7000" | findstr ESTABLISHED
```

### 4.2 云服务器（8.137.70.163，宝塔终端）

```bat
:: frps 是否在跑
tasklist | findstr frps

:: 后端是否在监听 8000
netstat -ano | findstr ":8000" | findstr LISTENING

:: 验证代理链路是否通（返回 401 说明通了，被中转站正常拦截）
curl --proxy http://127.0.0.1:8899 -I https://xibapi.com/v1/models
```

## 5. 修改前端后如何覆盖上传

### 5.1 本地开发

```bat
cd frontend
..\backend\venv\Scripts\python.exe dev_server.py 8001
```

访问 `http://localhost:8001` 预览（已禁用缓存，改完刷新即可）。

### 5.2 上传到服务器

前端目录：`C:\wwwroot\BoliAi\frontend`（Nginx root，全部是静态文件，**没有服务器专属文件**）

**推荐方式（宝塔面板）**：

1. 本地把 `frontend\` 整个目录压缩成 zip（**包含 css、js、*.html**）
2. 登录宝塔面板 → 文件 → 进入 `C:\wwwroot\BoliAi\frontend`
3. 上传 zip → 右键解压 → **选择覆盖同名文件**
   - 更稳妥：先删除旧目录里的 css、js、*.html 再解压，避免旧文件残留
4. 前端是静态文件，**无需重启任何服务**，浏览器强刷（Ctrl+F5）即可生效

> 别动 Nginx 配置（在宝塔「网站」里管理），除非要改端口/域名/反代规则。

## 6. 修改后端后如何覆盖上传

### 6.1 本地开发

```bat
cd backend
.\venv\Scripts\python.exe -m app.main
```

### 6.2 上传到服务器（⚠️ 重点：只能覆盖 app 目录）

后端目录：`C:\wwwroot\BoliAi\backend`

**服务器上以下文件/目录是专属的，绝不能覆盖**：

| 路径 | 说明 |
|------|------|
| `venv\` | Python 虚拟环境（几百 MB，覆盖会坏） |
| `.secrets\` | JWT_SECRET / ADMIN_KEY 密钥文件 |
| `config.env` | 数据库连接 + 代理配置 |
| `data\` | 运行数据（用户上传的参考图、供应商记忆） |

**后端代码全部在 `app\` 目录下**（main.py、core、api、db、schemas、services），所以：

**推荐方式（宝塔面板）**：

1. 本地只打包 `backend\app\` 目录成 zip
   - 若改了 `requirements.txt`，也一起上传
2. 宝塔 → 文件 → 进入 `C:\wwwroot\BoliAi\backend`
3. 上传 zip → 解压覆盖 `app\`（先删旧 `app\` 再解压最稳妥）
4. **什么都不用做** —— `watch_backend.py` 每 2 秒检测到变化会自动重启后端；
   如果改了 `requirements.txt`，它会先自动 `pip install` 再重启

### 6.3 重启后端（正常情况下不需要）

有 `watch_backend.py` 守护后，**覆盖任何文件都不用敲命令**：

| 覆盖内容 | 生效方式 |
|---------|---------|
| 后端代码 `app\*.py` | watch 检测到变化 → 自动重启（≤2 秒） |
| `config.env` | 同上，自动重启 |
| `.secrets\*` | 同上，自动重启 |
| `requirements.txt` | 自动 pip install + 重启 |

**只有改完 `watch_backend.py` 本身**（它不监控自己）或后端彻底卡死时，才需要手动重启守护任务：

```bat
:: 杀掉当前守护和后端（PID 以 netstat / tasklist 为准）
netstat -ano | findstr ":8000" | findstr LISTENING
taskkill /F /T /PID 进程PID

:: 重新拉起守护（会自动启动后端）
schtasks /Run /TN "BOLI_Backend_Watch"
```

排查问题时看后端运行日志：

```
type C:\frp\backend.log
```

## 7. 常见问题排查

| 现象 | 排查步骤 |
|------|---------|
| 生成图片报 `ConnectionResetError(10054)` | 1. 本地 `netstat` 看 8899 是否 LISTENING<br>2. 服务器 `tasklist` 看 frps 是否在跑<br>3. 服务器 `curl --proxy http://127.0.0.1:8899 -I https://xibapi.com/v1/models` 是否返回 401 |
| 前端打不开 | 1. 服务器 `netstat -ano \| findstr ":8000"` 是否有后端<br>2. 看日志 `type C:\frp\backend.log`<br>3. 宝塔 Nginx 是否运行<br>4. 浏览器强刷 Ctrl+F5 |
| 覆盖代码/配置后没生效 | 等 2-3 秒（watch 每秒检测）；还不行看 `C:\frp\backend.log` 是否有"检测到文件变化"记录 |
| 服务器重启后 frp 断 | 检查两台机器的 `BOLI_*` 任务计划是否都存在、是否允许开机自启；watch.bat 每分钟会自动拉起 |
| proxy.py 起不来（10013 端口被占） | 8899 被占，找到占用进程；或临时换端口（需同步改 frpc.toml 的 localPort/remotePort） |
| 生成报"[供应商] 代理连接异常"，但 GET /v1/models 走代理返回 401（链路通） | 大概率是 proxy.py 空闲超时掐断长连接：确认 BOLI_Proxy 启动命令带 `--timeout 900`，不带则按 3.2 改并重启任务 |
| frpc 进程在（tasklist 有）但云端 8899 不通 / 生成全挂 | frpc 是"僵尸连接"（进程在、隧道断）：`schtasks /End /TN "BOLI_Frpc"` + `schtasks /Run /TN "BOLI_Frpc"`；已增强 watch.bat 自动检测 |

## 8. 记住的几条铁律

1. **config.env / venv / .secrets / data 是服务器专属，永远不要覆盖**
2. 改代码只上传：前端 `frontend\` 整包 / 后端 `backend\app\`（+ requirements.txt）
3. frp 的 token 和端口，服务端、客户端必须一致，改配置要两边一起改
4. 后端请求走代理靠 config.env 里的 `HTTPS_PROXY`，**不用改代码**
5. 后端由 `watch_backend.py` 守护，覆盖任何文件自动重启生效，**不需要手动重启**
6. 云服务器、本地电脑的 `BOLI_Watch` 守护任务不要删，它负责崩溃自恢复
